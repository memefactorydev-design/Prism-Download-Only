# Prism AI — project conventions

- **New here?** `README.md` has the quick start; `DEPLOY.md` and `deploy/` cover hosting.

- **Two brands, never confused.** *Prism AI* is the PRODUCT (app chrome, logo, login, metadata — constants in `src/lib/brand.ts`: spectrum triangle mark in `src/components/ui/Logo.tsx` + `src/app/icon.svg`, obsidian "Refraction" design tokens in `globals.css`, Inter Tight/Fraunces/JetBrains Mono type). The CLIENT brand the marketing is FOR is **data, never prose**: one `BrandProfile` row per scope (`""` = the workspace, captured at `/welcome`; a member's id = their own), rendered by `renderBrandBrief` (`src/lib/brand-brief.ts`) into the brief every agent reads. No prompt file, default, placeholder or test may name a real business — `npm test` greps for it.

- **One posting core.** All publishing to Instagram/Facebook/TikTok/LinkedIn/YouTube/Pinterest/Google Business goes through `src/lib/postiz.ts` (channel → Postiz provider via `PROVIDER_ALIASES`; our `gbp` = Postiz's Google My Business). Channel agents differ in strategy only — never add per-channel API clients. Houzz has no posting channel (no API/Postiz support) — Houzz is research + manual presence only.
- **Auth is multi-user, two roles.** Session = HMAC cookie (`src/lib/session.ts`, role embedded); `src/proxy.ts` is the first fence (login redirect + admin-path blocks), route guards in `src/lib/auth.ts` (`requireAdmin`/`requireUser`, DB re-checked) are the second — never rely on the proxy alone for anything sensitive. Reports and user admin (/users) are admin-only. First login seeds the admin from ADMIN_EMAIL + DASHBOARD_PASSWORD. `/api/deals/webhook` (own shared secret) and `/s/*` (published sites) stay public; `/api/studio/upload` is proxy-exempt (streams GBs) and enforces the session in-route.
- **Beta users are sandboxed per user.** Postiz + Meta are PER-USER connections (`PER_USER_PROVIDERS` in `src/lib/connections.ts`; `Connection.userId`, `""` = the workspace/owner scope, admins share it): every member connects their OWN Postiz + Meta on /connections and can never read or write the workspace's. The rest of the stack (Anthropic, Gemini, Apify, ElevenLabs…) is the workspace engine, admin-managed, shared by all users. `Post`/`RoasSnapshot`/`Deal`/`MediaAsset`/`VideoJob`/`FableProject`/`Site`/`TrendInsight`/`ContentTemplate`/`ContentDraft`/`AdIdea` all carry `userId`; members see and act on only their own rows (helpers `scopeOf`/`scopeWhere`/`canTouch` in `src/lib/auth.ts`), posts publish through the post OWNER's Postiz (`pushToPostiz` uses `post.userId`), and worker renders inherit the JOB's scope. Approval gates stay server-side, but WHO decides is scope-based: the admin for workspace posts/ad budgets, each member for their own (their accounts, their spend, their risk) — enforced in `decidePost`/`decideAdApproval`, never in UI. Ad-budget approvals pin their scope in the payload (`scopeUserId`) and execute against that scope's ad account. External publishing (WordPress/FTP for sites and content) uses WORKSPACE credentials and stays admin-only; members publish in-app or export. Member activity (posts, deals, ad decisions, agent runs) is NOT journalled to the pipeline/named agents' dream memory — only workspace outcomes train the brand agents.
- **Every scope has a brand profile (`/brand`, `BrandProfile` table, `src/lib/brand-profile.ts`).** Prompt files are brand-agnostic and read the brief's fixed section headings (Overview, Audience, Positioning & USPs, Voice & tone, Locations & service areas, Goals, Channels, Competitors, Search & social, Visual identity, Seasonality, Creative licence — listed in `agents/BRAND.md`). `runAgent` takes `options.scopeUserId` and appends `brandTaskSuffix(scope)` — the scope's brief, or the neutral "not set up yet" note — to every task; member runs additionally skip dream journaling. Named agents get the same brief via `systemPrompt(id, scope)`. Thread `scopeUserId` through any NEW agent call site. SEO and GBP read the scope's `siteUrl`/keywords/locations from the profile and fail loudly ("add your website on /brand") without them. Onboarding (`/welcome`, `src/lib/onboard.ts`) scrapes the site, infers the profile, asks a quiz for what a site doesn't say, and is required for admins and members alike (skippable; the Overview shows a "finish setup" card).
- **Login is rate-limited** (`src/lib/rate-limit.ts`, in-memory: 5 failures/15min per email, 20 per IP, 15-min lockout) — fine while the app is one `next start` process per instance; move to the DB if that changes.
- **Two instances may run at once** (a laptop + a server): separate SQLite/data by design — no shared state, no conflicts. Rules: point the n8n deals webhook at ONE base URL; set `DREAMS_ENABLED=0` on one instance so agent memories evolve in exactly one place; remember both share the same live Postiz/Meta accounts, so approve a given post on one instance only.
- **Approval gates are server-side.** Anything that spends money, posts publicly, or changes ad budgets must create an `Approval` row and wait for a dashboard decision. Enforce in API routes, not in UI.
- **No hardcoded credentials.** Env vars only (`.env.example` documents them); OAuth tokens stored in the DB are encrypted with `src/lib/crypto.ts`.
- **Fail loudly on missing setup.** Unconnected services throw a "not connected yet — see Connections page" error; gated Meta features surface `pending_app_review` status. Never fail silently or fake success.
- **SQLite caveats.** No Prisma enums/Json on SQLite — status fields are validated strings, JSON payloads are stored as strings.
- **Engine layer (`src/lib/llm/`).** Every language-model call goes through `generateText`/`generateJson` in `src/lib/llm/index.ts` — never import `@anthropic-ai/sdk` anywhere else (Iris's native tool loop is the one grandfathered exception, and it only runs on the API engine). Three providers: `claude-cli` (spawns the user's own `claude -p --safe-mode`, bills their Claude plan), `codex-cli` (`codex exec --json --ignore-user-config`, bills their ChatGPT plan) and `anthropic-api` (the key). Selection: `LLM_ENGINE` env → `Setting` row → auto (key, then Claude Code, then Codex). Rules that keep us on the right side of both vendors' terms: Prism never reads, stores or forwards CLI credentials (`~/.claude`, `~/.codex/auth.json`, `CLAUDE_CODE_OAUTH_TOKEN`); it never modifies the binaries; it never passes `--bare` (bare mode drops the subscription login); readiness is read from `claude auth status` / `codex login status` only. Agent frontmatter `model:` is a TIER (opus/sonnet/haiku) that each provider maps to a real model. CLI runs go through one concurrency gate and nightly dreams are capped (`DREAMS_MAX_PER_NIGHT`) because a subscription has one shared usage window. Gate features on `engineStatus()`/`engineReady()`, never on `getSecrets("anthropic")`.
- **Sub-agents** live in `.claude/agents/` (supervisor is opus, rest sonnet). The backend invokes them via `src/lib/agents/run-agent.ts`; every agent name must be registered in `AGENT_NAMES`.
- **Templates** (`/templates`) is a standalone research function. `template-research-agent` (sonnet) takes Apify-scraped TikTok/Instagram top performers for a niche (`src/lib/templates.ts`, reuses `scrapeTrends`) and returns ranked **CapCut-style editing blueprints** + ready-to-post captions/hashtags for Instagram, TikTok, Facebook and YouTube, stored as `ContentTemplate` rows. Boundary: we produce **reproducible blueprints/recipes**, never importable CapCut project files and never other creators' actual video. "Use in Calendar" spins a prefilled draft via `createDraft`; "Use in Studio" (`/studio?template=<id>`) attaches the blueprint to a single-video job (`VideoJob.blueprint`) so `planReels` cuts the reel to that template's structure. Ad Ideas (`ad-research-agent`) tailor ideas across all enabled channels including YouTube.
- **Posts carry a content `format`** (`post|reel|carousel|story|short|video`) chosen per channel — options live in `FORMAT_OPTIONS` (`src/lib/posts.ts`, mirrored client-side in `CalendarBoard.tsx`). Format only *tightens* validation (`format:"post"` keeps prior behaviour). Postiz has no distinct reel/carousel `post_type`, so only `story` maps to a Postiz type; reel/carousel ride as `post`. **YouTube is a full posting channel** (video-only, needs a `title`); its exact Postiz settings are verified on first live call and fail loudly if wrong.
- **Video rendering runs in the worker, never a request.** ffmpeg/transcription work lives in `src/lib/video/*` and `src/worker/*`; API routes only enqueue `VideoJob`s. Keep the heavy ML/ffmpeg imports out of anything the Next bundle pulls in (`src/lib/studio.ts` is the light enqueue/read layer). Shell out to ffmpeg only via `src/lib/video/ffmpeg.ts` (uses the bundled `ffmpeg-static`/`@ffprobe-installer` binaries — never assume a system ffmpeg).
- **Trend research is an explicit exception to "official APIs only".** By explicit choice, Studio scrapes TikTok/Instagram/**YouTube**/**LinkedIn** via Apify (`src/lib/apify.ts`, `apify` connection) for viral-pattern research — subject to those platforms' ToS. Boundaries that stay: analyse **public metadata/patterns only** (never download/re-host other creators' videos), and surface the ToS + Apify-cost caveat in the UI. `tiktok-trend-agent`/`instagram-trend-agent`/`youtube-trend-agent`/`linkedin-trend-agent` distil scraped data into `TrendInsight` briefs that feed the reel/montage planners. Per-platform Apify actors are configurable via `APIFY_{TIKTOK,INSTAGRAM,YOUTUBE,LINKEDIN}_ACTOR`. All four platforms are topic/keyword based — **no fixed competitor lists**: research live-discovers the best-performing recent content for the entered niche (**LinkedIn** via `harvestapi/linkedin-post-search`, relevance-sorted, last month). The full channel stack (Instagram, Facebook, TikTok, LinkedIn, YouTube) is supported across trend research, templates per-platform copy, the calendar composer, the AI optimiser, and ad ideas.
- **Research agents are niche-faithful.** Trend and template agents research the **exact topic/niche the user enters** — they must NOT force the brand's own industry onto an unrelated niche (a niche the user enters stays that niche). They apply the brand's craft to whatever niche is asked for.
- **Drafts split caption vs hashtags.** When Studio clips or Templates create a calendar draft, `splitCaptionHashtags` (`src/lib/posts.ts`) puts the caption in the caption field and all `#tags` in the hashtag field. The **channel-copy-agent** (`POST /api/posts/optimize`, "✨ Optimise for <channel>" in the composer) rewrites caption + hashtags for the chosen channel using that platform's conventions + `relevantTrendInsights`.
- **Google Ads mirrors Meta exactly** (`src/lib/googleads/api.ts`, agent `google-ads-manager`): GAQL insights → RoasSnapshot rows (`network` column separates the two), analysis → `ad_budget` Approval rows (payload carries `network` + `scopeUserId`), execution (budget/pause/enable) ONLY via `decideAdApproval`. The `googleads` connection is per-user (developer token + OAuth client + refresh token + customer id; full setup steps on the Connections card). Google's `conversions_value` is never presented as banked revenue — the Deal ledger stays the truth.
- **SEO audits use REAL search data when `gsc` is connected** (`src/lib/gsc.ts`, service-account JSON + property; per-user): `runSeoResearch` injects measured queries/pages/CTR/positions as evidence and tells the agent to say so in caveats when it's missing. `/api/seo/search-performance` feeds the dashboard panel.
- **Leads CRM (`/leads`, `src/lib/leads.ts`)**: statuses new/contacted/booked/lost/callback/no_contact (validated strings), heuristic score on capture (transparent: contactability/context/source), `lead-scorer-agent` deep-score on demand. Kanban (dnd-kit) + list. `/api/leads/webhook` (own `LEADS_WEBHOOK_SECRET`, public in proxy) takes site-form/n8n leads into the workspace book. Booked/lost outcomes journal to marketing-supervisor (workspace scope only).
- **Newsletter (`/newsletter`, `src/lib/newsletter.ts`)**: audience = subscribed Leads (optionally one status), compose manually or via content-writer-agent, "send" flips status to approved and THE WORKER sends (`src/worker/send-newsletter.ts`) via the scope's own per-user `smtp` connection, paced, with per-recipient failure counts. Every email carries an HMAC-signed one-click unsubscribe (`/api/newsletter/unsubscribe`, public; signed with TOKEN_ENCRYPTION_KEY; APP_BASE_URL builds the link). No SMTP connection = loud failure.
- **ROAS = spend vs WON DEALS, not pixels.** `/ads` leads with a monthly Spend-vs-Revenue table (`src/lib/deals.ts` `spendVsRevenue`): Meta spend from RoasSnapshot rows joined to the `Deal` ledger — real won business logged manually on /ads or pushed by the CRM/n8n to `POST /api/deals/webhook` (header `x-webhook-secret` = `DEALS_WEBHOOK_SECRET`). High-ticket kitchen sales close offline, so pixel-conversion revenue is never presented as ROAS. Won deals journal to meta-ads-manager's dream cycle.
- **Stock (Pexels) and alternative engines (fal.ai) are normal connections.** `pexels` powers the media library's "Find stock" search/import (`src/lib/pexels.ts`, downloads pinned to Pexels hosts) — imported files are plain MediaAssets usable everywhere. `fal` is the PRIMARY video provider, PLAN-ROUTED` in `src/lib/fal.ts`): Kling 3.0 standard for starter/growth (~1/3 the cost, near-parity quality, best photo fidelity), Seedance 2.0 Fast for agency/enterprise AND unset/owner deployments (best shot-to-shot consistency — the upper-tier USP). Both text-to-video + image-to-video (queue API, env-overridable `FAL_VIDEO_MODEL`/`FAL_KLING_MODEL`, shared per-render cap `SEEDANCE_MAX_SECS` = 15s); morph bridges are pinned to Seedance (`end_image_url` live-proven). Veo (Gemini) is the automatic BACKUP ONLY — never a primary (5× Kling's price + drift/hallucination in the the product decision). An empty fal balance fails loudly with fal's own message. ALL images app-wide use Gemini Nano Banana latest (`GEMINI_IMAGE_MODEL`, default nano-banana-pro-preview) — FLUX was removed 2026-07-12 with the owner's engine consolidation.
- **Video generation is the one hard-capped unit (`src/lib/quota.ts`).** `PRISM_PLAN` (starter/growth/agency/enterprise, set per customer deployment) grants a monthly workspace-shared allowance of AI video generations (10/40/120/300; `VIDEO_QUOTA_OVERRIDE` for bespoke deals; unset = uncapped pre-billing behaviour). Enforcement is fail-loud at the user-facing routes (ad clip; the ad-film route gates ceil(target/cap) renders up-front so jobs never die mid-render on quota) and degrade-only inside renders (morph bridge → free dissolve, site hero video → gradient block). Every video spend must flow through `meterUsage(..., "video_gen", ...)` — the quota counts those events; everything else stays on the /usage soft count.
- **Music is royalty-free only.** Studio never uses Spotify/commercial audio in videos (DRM + no sync licence). The ONLY music engine is **Eleven Music** (`generateMusic` in elevenlabs.ts + `src/lib/music.ts` — composes an original commercially-cleared track from a vibe prompt, sized to the cut; needs the `music_generation` permission on the key; "✨ Compose" in MusicPicker, `POST /api/music/generate`, Director 'Composing the score'). The one other music source is user uploads. Jamendo was removed 2026-07-12 at the the product decision — do NOT reintroduce third-party music libraries. Composed/uploaded tracks are `MediaAsset`s reused via the existing `musicAssetId`.
- **Beat-sync is estimate-based.** Beat detection (`src/lib/video/beat.ts`, music-tempo) runs on the music track and snaps montage cut lengths to the beat grid; on low confidence it returns null and the render falls back to even cuts. Worker-side only; keep music-tempo out of the web bundle (only `beat.ts`/worker imports it).
- **Time is modelled ONCE (`src/lib/video/timeline.ts`).** `buildTimeline(segments, beatDurationsMs?)` bakes trims, beat clamps (source-domain: `srcSpan = min(span, beat×speed)`) and per-segment `speed` into `TimelineEntry[]`; captions (`buildAss`), emoji pops, SFX delays, track-pan keyframes and every ffmpeg trim/outDur consume the SAME entries — never hand-roll output-time math (the old inline `offsetMs +=` accumulators are gone on purpose). **Speed ramps** (`EdlSegment.speed`/`FableScene.speed`, enum 0.25-2 in `transitions.ts`) retime video via `setpts/(speed)`+fps=30; speed ≠ 1 FORCE-MUTES that segment's audio (sanitizers enforce; no atempo ever). **Transitions** (`transition: cut|dissolve|morph`, "how a segment ENTERS") are materialized in the workers as first-class muted bridge segments spliced into the exec list — dissolve = free ffmpeg still-crossfade (0.6s); morph = Seedance `end_image_url` bridge (`src/lib/video/morph.ts`, 4s render time-compressed to 1.3s, frames pre-cropped to 9:16, content-hash cached as `morph-<hash>.mp4` MediaAssets, metered per bridge). Caps enforced by DOWNGRADE never failure: 2 morphs/cut (sanitizers), `MORPH_MAX_PER_JOB` 4 per montage job (`VideoJob.morphs` opt-in toggle), Director drafts always dissolve. Single-mode planReels deliberately has NO speed/transition in its schema (that path stays byte-identical); voiceover mode's only ramp is the auto-rescue (footage slowed ≤0.5x to cover a long narration).
- **Director projects accept PHOTOS as sources (2026-07-12).** A photo FableSource gets a nominal `PHOTO_ANIMATE_MS` (8s) window; the agent cuts scenes within it and writes a per-scene `motion` direction; `processFableRender` animates each distinct (photo, motion) pair ONCE on the plan's fal engine (`src/lib/video/animate.ts`, content-hash cached as `animate-<hash>.mp4` MediaAssets, metered `{kind:"animate"}`), splices the clip in as a new source and re-points the scene — downstream (timeline, captions, bridges) treats it as normal footage. Photo scenes are force-muted by the sanitizer. Animation is CORE content: failures fail the job loudly (unlike bridges), and the render route pre-gates the whole animation count against the video quota. Photo-ness derives from MediaAsset.mimeType — no schema flag.
- **Trend insights are topic-matched.** Planners use `relevantTrendInsights(text)` (keyword overlap with the video's transcript, recency fallback), not just the newest globally.
- **Director (`/director`, internal namespace `fable*`) is the conversational AI video editor.** A project's STATE is its `FablePlan` JSON (like `Page.html` in the site builder); `fable-director-agent` (**opus**) amends the COMPLETE plan every chat turn via `runAgent` structured output (`src/lib/fable.ts` — schema, sanitizer, `planToEdlClip`, task builder; NO ffmpeg imports, web-bundle-safe). Renders are explicit and two-tier — draft 480p (ultrafast) vs final 1080p — freezing the plan into an immutable `FableRevision` + `VideoJob` (`mode:"fable"`); `fable_prep` probes/transcribes sources once per project. The executor (`src/worker/process-fable.ts` + `renderFableClip`) is pure execution: a music 'search' composes an Eleven Music track then PINS it into the plan, VO via the TTS cache (`src/lib/video/tts-cache.ts`, sha256(script+voice) under `data/tts`), VO captions win over dialogue captions. ffmpeg gotchas learned the hard way: emoji overlay loops need `shortest=1`, and multi-scene graphs must use ONE interleaved concat (`v=1:a=1`) — separate video/audio concats + loudnorm make ffmpeg emit duplicate video frames.
- **Ad films are stitched from capped renders (`VideoJob.mode "adfilm"`).** Video engines can only render short clips, so `/api/adstudio/film` enqueues a worker job (`src/worker/process-adfilm.ts`): `ad-video-director-agent` (opus) writes a shot list — every segment within the engine's HARD per-render time limit — plus a VO script; each segment renders on Seedance (Veo per-segment backup) and its {engine, capSecs, requestedSecs, actualSecs} is recorded in `VideoJob.renderLog`; the frozen plan then reuses the fable executor for the stitch (ONE interleaved concat) with the ElevenLabs voice-over and word-synced captions on top. ElevenLabs is REQUIRED for ad films (VO + captions) — fail loudly, never render silent.
- **Studio has three modes; keep them separate.** `VideoJob.mode` adds `"voiceover"` (one source → `processVoiceover`: context transcript → `voiceover-script-agent` writes narration sized to the footage → ElevenLabs TTS **with word timestamps** (`src/lib/elevenlabs.ts`) → captions burned from the TTS alignment (no STT drift) → VO mixed over a ducked source bed + optional music). ElevenLabs is a normal encrypted connection (`elevenlabs`), fail-loudly when absent.
- **ALL speech runs through ElevenLabs.** Voice-overs = ElevenLabs TTS with word timestamps; captions = burned from those timestamps (VO) or from Scribe transcripts (dialogue); transcription = ElevenLabs Scribe (`src/lib/video/transcribe.ts`, `ELEVENLABS_STT_MODEL` default scribe_v2, word-level timestamps) — the local Whisper path was removed WITH the owner's consent, so source audio IS uploaded to ElevenLabs for transcription. Fail loudly when the connection is missing; `@huggingface/transformers` stays a dep for reframe.ts subject tracking only.
- **Captions/effects/SFX are style- and planner-driven.** Caption styles (`caption-styles.ts`) carry full visual identity (font/size/outline/box/position/pop) incl. premium styles (beast/luxe/neon/boxed); emojis render as Twemoji PNG overlay "pops" (`src/lib/video/emoji.ts` — libass can't do colour-emoji fonts; PNGs cached in `data/emoji-cache`), placed by planner `emojiHints` (exact spoken word + emoji). Segments carry a duration-preserving `effect` (`punch_in`/`zoom_drift`/`flash_cut`); SFX come from a one-time-generated ElevenLabs library cached in `data/sfx` (skipped silently without the key — decoration, never a blocker). Single mode supports a music bed **sidechain-ducked under dialogue**. All toggleable per job (`effects`/`sfx`).
- **Studio has two source modes; keep them separate.** `VideoJob.mode` is `"single"` (one source → `processJob` main path, `planReels`, `renderClip`, supports tracking + tight-edit) or `"montage"` (many sources via `VideoSource` rows → `processMontage`, `planMontage`, `renderMontageClip`, centre-crop + supercut). The single path is the original architecture and must stay intact — add montage behaviour in the montage functions, don't fold it into the single ones.
- **SEO/GEO suite lives at `/seo`** (tabs: Audit · Content · Google Business). `seo-geo-agent` returns a **structured** audit (`runSeoResearch` in `src/lib/seo.ts` — live-site fetch + `src/lib/serp.ts` Google SERP scrape) with copy-ready fixes incl. JSON-LD; `content-writer-agent` (`src/lib/content.ts`) writes SEO+GEO blog/FAQ `ContentDraft`s (answer-first, Article/FAQPage schema); `gbp-agent` (`src/lib/gbp.ts`) drafts a Google Business Profile plan from scraped Maps/SERP. GBP posts publish through the normal Calendar approval gate on the `gbp` channel (Postiz Google My Business); the GBP board's "Send to Calendar" creates those drafts, with copy-paste kept as the manual fallback.
- **Website/landing-page builder at `/sites`.** `web-designer-agent` (**opus**) returns a complete self-contained HTML document; `src/lib/builder.ts` streams it. `Site`/`Page`/`BuilderMessage` model it; the builder UI is chat + sandboxed-iframe live preview + code view + publish/export.
- **Publishing is one subsystem** (`src/lib/publish.ts`) with pluggable targets: `in_app` (served publicly at `/s/<slug>` via `src/app/s/[slug]/[[...path]]/route.ts`), `export`, `wordpress` (REST upsert by slug), `ftp`/`sftp` (upload). New encrypted connections: `wordpress`, `ftp`. External/production pushes are owner-confirmed in the UI and logged to `PublishLog`; in-app hosting of owner-built pages is a direct action. FTP libs (`ssh2-sftp-client`/`basic-ftp`) are in `serverExternalPackages` (next.config) — server-only, never the client bundle.
- **All pipeline agents run on Claude Opus 4.8**. To trim spend later, flip individual agents' frontmatter back to `sonnet`.
- Build proceeds in phases (see README status list); check in with the owner at the end of each phase.

- **Iris is the product's own guide (2026-07-13), separate from both agent systems.** `src/lib/iris.ts` + `/api/iris/*` + the rewritten `HelpLauncher`: a support chat that knows the help.ts manual + the member's brand/connections/quota, and raises `SupportTicket` rows (admin queue at /tickets, resolution notes flow back into the widget and Iris's context). SECURITY IS STRUCTURAL, keep it that way: the model is never told vendor names/infra/owner (context minimisation — statuses pre-aliased via STACK_ALIASES), hard refusal rules, and a deterministic post-scrub (`scrubReply`/`containsBanned`) that replaces any reply touching a banned internal term and freezes streamed deltas. Never inject vendor identifiers into Iris's prompt.
- **The named agent team is a separate system from the pipeline agents.** Pipeline agents (`.claude/agents/*.md`, invoked via `run-agent.ts`) power features; the eleven NAMED agents (`agents/<id>/` — AGENT/SOUL/SKILLS + shared BRAND.md) are user-facing personas with persistent memory. Never machine-edit the human-authored AGENT/SOUL/SKILLS/BRAND files; the system only writes each agent's `MEMORY.md` and `LEARNINGS.md` (capped, via `src/lib/memory.ts`).
- **Named-agent state is file-based on purpose** (`data/journal/*.jsonl`, `data/dreams.json`, `data/agent-state.json`, gitignored): user-editable, portable, append-only journal. Don't migrate it to Prisma without a reason.
- **Engine router (`src/lib/engine.ts`):** named-agent chat uses Claude Opus when the anthropic connection exists; anything needing live Google Search grounding uses Gemini (`gemini` connection), which is also the fallback. Gemini additionally powers ALL app images (Nano Banana latest) and backup video (Veo) via `src/lib/gemini.ts` — both accept the owner's REAL photos: `geminiImage(prompt, sourceImages)` edits/composes them, `startVeoVideo(prompt, firstFrame)` animates from one as the opening frame (Ad Studio's photo picker feeds these; existing *videos* become ads via the Studio clip pipeline instead — Veo takes no video input).
- **Dreams run in the worker** (`dreamTick` from the poll loop, `DREAM_HOUR` env, default 3am) — the worker is the app's only persistent process. **ALL agents dream**: the 11 named agents AND every pipeline agent. Pipeline runs are journalled by `runAgent()`/`builder.ts`; owner decisions (idea status, template use, post approve/reject, ad-budget decisions, content publishes) are journalled as `outcome` entries to the owning agent; dreams rewrite each agent's MEMORY/LEARNINGS (named → `agents/<id>/`, pipeline → `data/pipeline-memory/<name>/`), which `memoryPromptSuffix()` injects into every subsequent run. Dream cycles skip agents with no new journal entries.
- **Intel (`src/lib/intel.ts`) vs trend research (`src/lib/apify.ts`) stay separate:** intel briefs feed the named agents (chat + dreams); trend insights feed the Studio planners. Both call Apify through the ONE shared runner (`src/lib/scrape.ts`) and surface ToS/cost caveats. Research is always live-discovery of top performers — never fixed competitor lists. Every research output can become a post: intel briefs and trend insights have "draft post" actions (`/api/intel/[id]/draft`, `/api/trends/[id]/draft` → channel-copy-agent → calendar draft), and templates/'Use in Calendar' covers all seven channels.
